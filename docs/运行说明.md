# 运行说明（当前状态）

> 记录**实际代码**的线程结构、启动顺序、延迟构成和扩展点。标「实测」的是在本机跑出来的，标「估算」的是按代码推的。

## 1. 一句话架构

**单进程 + 多线程**，没有前后端分离，也不开本地端口。
Qt 事件循环负责所有 UI；耗时的活（抓屏、识别、模型加载、合成）全丢后台线程，用 Qt 信号回主线程更新界面。

```
主线程 (Qt)
 ├─ 悬浮球 Orb        30fps 自绘动画
 ├─ 气泡 Bubble       流式文字 + 输入框
 ├─ 设置 / 历史窗
 └─ AssistantApp      状态机与调度

后台线程
 ├─ HotkeyListener ×2   Win32 消息循环，F2 / Ctrl+F2
 ├─ WakeListener        通话模式：常开麦克风 + 断句
 ├─ Speaker.synth       文字 -> PCM（edge-tts）
 ├─ Speaker.play        PCM -> 声卡
 └─ QThread 任务        抓屏+问答 / ASR / OCR / 模型加载
```

## 2. 启动顺序

| 时刻 | 发生什么 |
|---|---|
| 0 ms | 双击快捷方式，PyInstaller 启动器加载 _internal |
| ~0.4 s | Python 起来，import PySide6（实测 85ms）+ 各模块 |
| ~0.5 s | QApplication 创建（实测 7ms） |
| ~0.55 s | Settings.load() 读 config/settings.json |
| ~0.6 s | 构建悬浮球和气泡（实测 39ms），**球出现**；系统托盘出现图标（不占任务栏按钮） |
| ~0.6 s | 注册全局热键 F2 / Ctrl+F2 |
| ~0.6 s | 同步菜单开关；上次开着通话模式就开始加载 ASR |
| 0.9 s | 没有 Key 且没打过标记 → 弹「欢迎使用」设置窗 |
| 12 s | 后台预加载 ASR + OCR 预热（约 10 s CPU，不挡 UI） |

源码启动实测 62ms（不含 Qt 导入）。打包版自检总耗时 11.7s，来源码版 11.8s——
说明 onedir 启动器开销 **小于 0.5 秒**。

## 3. 一次问答的链路

```
F2 ──► 开麦录音 ──► (同时) 抓屏 0.14s ──► 后台 OCR 2.2s
                    │
                    └─ 静音 0.78s 自动停 ──► whisper 识别 1.4s
                                                    │
                                         抓好的图 + OCR 文字 + 问题
                                                    ▼
                                       DeepSeek 流式（首字 1.6s）
                                                    │
                                   ┌────────────────┴───────────────┐
                                   ▼                                ▼
                         气泡逐字显示                      按句切分 → edge-tts → 播放
```

**关键设计：抓屏和 OCR 跟「你说话」并行**，所以它们再慢也不占等待时间。

### 实测延迟（本机，3.34 秒的提问）

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 抓屏 | 0.14 s | 与说话并行 |
| OCR | 2.2 s | 与说话并行，说完没算完就跳过 |
| ASR | **1.42 s** | 串行，CPU |
| 模型首字 | **1.62 s** | 串行，网络 |
| TTS 首句 | **2.11 s** | 串行，网络 |
| **合计：说完 → 第一声** | **≈ 5.2 s** | 后续句子边播边合成，不断档 |

## 4. 通话模式的循环

```
麦克风常开 ──► 能量 VAD 切句（静音 0.62s）──► 整句转文字
                                                    │
                                            匹配唤醒词（精确 + 去空格模糊）
                                                    │
                         ┌──────────────────────────┴──────────┐
                         ▼                                     ▼
                带问题：「小助手，这BOSS…」            只喊了词：「小助手」
                         │                                     │
                 先播唤醒应答「主人，我在」              先播应答
                         │                                     │
                    直接答题                          等应答播完再开麦听
```

三个约束：
1. **忙的时候不接话**：录音/思考/朗读期间，片段直接丢（enabled() 为假）。
2. **自己说话不录自己**：开麦前确认 speaker.busy 为假，最多等 4 秒兜底。
3. **模型不能并发**：WhisperASR.transcribe() 加了锁，唤醒线程和主线程排队。

## 5. 数据都在哪

| 路径 | 内容 |
|---|---|
| config/settings.json | 全部配置（含 API Key）；安装包**不打包**这个文件，首启时由向导生成 |
| data/history.jsonl | 对话记录，一行一条，追加写 |
| models/ | whisper 模型，464MB |
| dist/GameAssistant/ | 打包产物，整个文件夹可以拷走 |

## 6. 已知瓶颈

- **ASR 是线性的**：CPU 上 RTF≈0.42，10 秒的问题要 4.2 秒。问得越长等得越久。
- **TTS 首句 2 秒**：edge-tts 要走网络，而且是整句合成完才开始播。
- **唤醒词靠 whisper**：每句话都要跑一次识别，游戏声外放会误触发。
- **单帧视觉**：只有一帧，没有连续画面跟踪，也不知道你 3 秒前干了什么。
- **独占全屏**：盖不上任何窗口，必须无边框窗口化。

## 7. 可扩展方向

| 方向 | 改动面 | 收益 | 风险 |
|---|---|---|---|
| **边说边识别** | voice/recorder.py + voice/asr.py：按住时每 800ms 对累计音频转一次，只用最后结果 | −1.4 s | 中：CPU 翻倍，可能卡游戏 |
| **TTS 流式播放** | voice/tts.py：不等整句，边合成边解码 | −1.0 s | 中：mp3 增量解码麻烦 |
| **换本地 TTS** | 新增 voice/tts_local.py，接 CosyVoice / GPT-SoVITS | 首句 →0.3 s，离线 | 高：8G 显存和游戏抢 |
| **本地 wiki 库** | 新增 know/：爬 BWiki → bge-m3 → Chroma | 检索更准、可离线 | 低：纯增量，不动主链路 |
| **游戏 profile** | config/games/*.json：热词表、wiki 源、UI 区域 | 冷门游戏也能读懂 | 低 |
| **连续对话** | 回答完自动再听 N 秒，不用重新喊唤醒词 | 体感像真人 | 中：回声 / 误触发 |
| **Live2D 形象** | 换 ui/orb.py 的绘制层，引入渲染器 | 好看 | 高：Python 绑定不成熟 |
| **手机 / 双屏** | Core 抽成 WebSocket 服务，另做前端 | 竞技游戏免 overlay | 中：要拆进程 |

**按性价比推荐的前三个**：本地 wiki 库（低风险高收益）→ 边说边识别（解决体感）→ 游戏 profile。
