# 双模式改造方案（游戏 / 办公）

> 目标：保留现在 5 秒级的游戏问答体验，同时提供一个能真正操作电脑的办公模式。
> 办公模式内置 DeepSeek Harness（Node 运行时 + 裁剪后的 dsh），不依赖用户另装。

## 1. 总体结构

```
            共享层（现有，基本不动）
  麦克风/ASR · TTS · 抓屏+OCR · 气泡 · 球 · 托盘 · 热键 · 设置
                    │
        ┌───────────┴────────────┐
        │                        │
   游戏模式                    办公模式
   DeepSeek 直连              内置 dsh 子进程
   单轮 + 搜索                 多轮 agent
   5.2s 端到端                 5~60s/任务
   历史：data/history.jsonl    会话：DSH session
```

**边界原则**：两个模式不共享上下文、不共享模型参数、不共享 UI 状态。
唯一共享的是“采集”和“呈现”——这是增量最大的部分。

## 2. 两种模式的差异

| 维度 | 游戏模式 | 办公模式 |
|---|---|---|
| 触发 | F8 / 触发词 | Ctrl+F9 / 托盘切换 |
| 延迟预期 | 5 秒 | 10~60 秒 |
| 能做什么 | 看屏幕、查攻略、答疑 | 跑命令、改文件、查资料、写文档 |
| 不能做什么 | 操作电脑 | 看游戏画面（不需要） |
| 权限 | 只读截屏 | workspace-write（默认） |
| 看屏幕 | 自动（可关） | 可选，默认不带截图 |
| 工作区 | — | `文档\语音助手\workspace` |
| 取消 | 语音打断 | 气泡上「停止」按钮 |

## 3. 办公模式内部设计

### 3.1 进程

```
VoiceAssistant.exe
  └─ 子进程：vendor/node/node.exe vendor/dsh/.../cli.js headless --json "任务"
       env: DEEPSEEK_API_KEY   （用设置里那个 key）
            DSH_HOME          （指到 data/dsh_home，不污染 ~/.dsh）
            DSH_PERMISSION_MODE（read-only / workspace-write / danger-full-access）
       cwd: 用户配置的工作区目录
```

- **冷启动约 1.5~2 秒**，之后每轮对话再加 1~3 秒
- `--json` 输出 NDJSON，逐条解析成 UI 步骤
- 取消 = `taskkill /T /F /PID`（杀进程树）
- 超时默认 180 秒，可调

### 3.2 权限模型（三层）

| 层 | 机制 | 效果 |
|---|---|---|
| 系统沙箱 | `DSH_PERMISSION_MODE=workspace-write` | 只能写工作区，越界直接失败 |
| 工作区 | 进程 `cwd` 指向配置目录 | 它连路径都看不到别处 |
| 人工确认 | 任务含「删除/清空/覆盖/卸载」等词 | 先复述一遍，点确认才执行 |

实测结论：headless 里没有人可以批准，**需要审批的操作会直接失败**，不会静默放行。

### 3.3 会话

- 每次任务用 `--session-id <固定id>` 续接，同一件事不用重复背景
- id 存在 `data/office_session.json`，可「新开会话」清空

### 3.4 屏幕与截图策略（隐私相关）

> **已实现**（2026-10-25）：默认只截前台窗口矩形，整屏改成了窗口级。
> 实测：2560×1600 整屏 → 1923×1234 的窗口，旁边的窗口不会被拍进去。

原计划分四层：

| 层 | 做法 | 状态 |
|---|---|---|
| **范围** | 只截**前台窗口矩形**，不是整个显示器 | ✅ 已实现 |
| **开关** | `capture_enabled` 关掉后永不自动截；气泡上给「📷 补一张」手动补 | 开 |
| **黑名单** | 前台窗口标题命中「密码 / 银行 / 1Password / KeePass / 微信 / QQ」→ 不自动截，提示原因 | 开 |
| **办公模式** | 默认**不附截图**；气泡上有「📷 带上屏幕」勾选，勾了才抓 | 关 |

另外两个已有的保护：抓帧发生在气泡弹出**之前**（不会把自己的界面拍进去）；只抓一帧，不录屏。

办公模式带图时：截图存到工作区 `.shots\` 下，任务文本里附路径，让 dsh 自己决定读不读；任务结束删掉。

## 4. UI 改动

### 4.1 悬浮球

- 游戏模式：现在这样（蓝/绿/黄/紫）
- 办公模式：外圈加**方形描边**，颜色改青绿，一眼区分
- 办公任务运行中：球变成“忙碌”动画（转动的方框）

### 4.2 气泡（新增“任务卡”形态）

```
┌──────────────────────────────────┐
│ ● 办公模式        运行中 01:23    │
├──────────────────────────────────┤
│ ✓ 读取目录结构                    │
│ ✓ 识别出 37 个截图                │
│ ◐ 正在移动到 2026-10/            │
│ ○ 生成汇总                        │
├──────────────────────────────────┤
│              [停止]  [收起]       │
└──────────────────────────────────┘
```

步骤来自 `--json` 事件流：`tool_call` → 一行，`tool_result` → 更新状态。
完成后折叠成一句结论 + 「查看详情」。

**语音**：办公模式只念开始和结束，不逐步播报（否则太吵）。

### 4.3 设置（新增一页「办公」）

- 工作区目录（选择器）
- 权限级别：只读 / 工作区可写 / 完全（默认只读？见待确认）
- 超时秒数
- 「新开会话」按钮
- 组件状态：内置版本号、体积

## 5. 目录与打包

```
vendor/
  node/            node.exe + 运行时（87 MB）
  dsh/             裁剪后的 dsh（307 MB，含 Office 组件）
data/
  office_session.json
  dsh_home/        隔离的 DSH_HOME
```

| 项 | 现在 | 改造后 |
|---|---|---|
| 安装后 | 931 MB | **~1.33 GB** |
| 安装包 | 547 MB | **~900 MB** |

构建脚本：

- `packaging/bundle_dsh.py`：解 asar → 裁剪 → 输出 `vendor/dsh`（这次实验的提取器可直接复用）
- `packaging/fetch_node.py`：下载 Node 24.x 官方 zip → 解压到 `vendor/node`
- `build.spec` 增加 `vendor/` 到 datas
- `installer.iss` 一并打包

## 6. 安全与隐私

- 办公模式**不上传截图**（它看不到屏幕），只上传任务文本
- 默认 `workspace-write`，写不了工作区外
- `DSH_HOME` 隔离，不动用户的 `~/.dsh`
- 遥测：`@deepseek-ai/dsh-otel` 会尝试上报，内置时应设法关闭（待验证环境变量）
- 重新分发需保留 DSH / Node 的 LICENSE 与 NOTICE

- **交互打磨**
  - 确认后气泡立刻收起，任务在后台跑；点球可以随时看进度，再点收起
  - 确认卡输入框多行自适应（最多 6 行），按内容长高，可直接改字后回车
  - 点「取消」直接关掉气泡，不留提示条
  - 完成朗读只念第一句（≤60 字，去掉 markdown 符号），不再念整段
